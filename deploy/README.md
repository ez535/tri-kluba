# Запуск «Трёх клубов» на своём сервере

Игра — один процесс Node.js без внешних библиотек, база — один файл SQLite. Перед игрой стоит Caddy: он сам получает HTTPS-сертификат для вашего домена. Docker не нужен.

## Что понадобится

- **Сервер** с Ubuntu 24.04: 2 ядра, 2 ГБ памяти, 20 ГБ диска. Основной и резервный — **в России, у двух разных провайдеров**: например, основной в Timeweb Cloud, резервный в Selectel.

### Почему оба сервера в России

- С 2025 года доступ из России к зарубежным хостингам ограничивают целыми сетями: соединение открывается, но через несколько пакетов зависает. Игра держит одно долгое соединение на весь матч, поэтому на зарубежном сервере она встала бы первой.
- Персональные данные российских пользователей (Telegram ID, имя) по закону должны сначала записываться в базу в России.
- Резерв у другого российского провайдера спасает от сбоя, блокировки аккаунта или подорожания у первого.

Сервер в Казахстане имеет смысл позже и отдельно, если появится заметная аудитория из Казахстана и других стран СНГ. Тогда выбирайте хостера со своей сетью в Казахстане, а не перепродающего серверы в чужих сетях.
- **Домен**, у которого A-запись указывает на IP сервера. Без HTTPS Telegram не откроет игру как Mini App, а смена сервера — это просто смена A-записи.
- **Бот** от @BotFather (можно добавить позже).

## 1. Установка (10 минут)

Подключитесь к серверу. Провайдер присылает IP и пароль root. На компьютере откройте Терминал (macOS) или PowerShell (Windows) и выполните:

```
ssh root@IP-сервера
```

Затем на сервере, подставив свой домен:

```
apt-get update && apt-get install -y git
git clone https://github.com/ez535/tri-kluba /opt/tri-kluba
bash /opt/tri-kluba/deploy/setup.sh игра.ваш-домен.ru
```

В конце скрипт напишет «Готово» и адрес игры. Если сайт не открылся сразу, подождите пару минут, пока обновится DNS и выпустится сертификат.

## 2. Подключение Telegram

1. В @BotFather: `/newbot` → получите токен. **Никому его не присылайте**, в том числе в чат с Claude.
2. На сервере откройте настройки и впишите токен в строку `BOT_TOKEN=`:
   ```
   nano /etc/tri-kluba.env
   ```
   Сохранить — Ctrl+O, Enter, выйти — Ctrl+X.
3. В @BotFather: `/newapp` → выберите бота → URL `https://игра.ваш-домен.ru` → придумайте короткое имя, например `play`. Впишите его в `APP_SHORT_NAME=`.
4. Перезапустите игру: `systemctl restart tri-kluba`.

Проверка: напишите боту `/start` — придёт кнопка «Играть». Добавьте бота в групповой чат и выберите в меню команду `/play`: бот создаст комнату для чата, а итоги матчей будет присылать туда же.

## 3. Резервный сервер

Резерв арендуйте у другого российского провайдера, не у того, где стоит основной сервер. На нём выполните шаг 1 с тем же доменом, а затем остановите игру, чтобы она не работала дважды:

```
systemctl disable --now tri-kluba caddy
```

На основном сервере настройте ночную отправку копии базы на резерв:

```
ssh-keygen -t ed25519 -N "" -f /root/.ssh/id_ed25519
ssh-copy-id root@IP-резерва
```

и впишите в `/etc/tri-kluba.env` строку `RESERVE_SSH=root@IP-резерва:/var/backups/tri-kluba`.

### Переезд на резерв

1. На резерве возьмите последнюю копию:
   ```
   ls /var/backups/tri-kluba
   gunzip -c /var/backups/tri-kluba/game-ДАТА.sqlite.gz > /var/lib/tri-kluba/game.sqlite
   chown tk:tk /var/lib/tri-kluba/game.sqlite
   systemctl enable --now tri-kluba caddy
   ```
2. У регистратора домена поменяйте A-запись на IP резерва. Через несколько минут игроки окажутся на новом сервере по той же ссылке.

## Как обновляется игра

Каждые 10 минут сервер проверяет репозиторий на GitHub. Если там новая версия, он прогоняет тесты и перезапускается. Пока идут матчи, он не перезапускается, а если тесты не прошли, остаётся на старой версии. Выключить: `AUTO_UPDATE=0` в `/etc/tri-kluba.env`.

## Полезные команды

| Что сделать | Команда |
|---|---|
| Работает ли игра | `systemctl status tri-kluba` |
| Журнал | `journalctl -u tri-kluba -n 100` |
| Обновить прямо сейчас | `bash /opt/tri-kluba/deploy/update.sh` |
| Сделать копию базы | `bash /opt/tri-kluba/deploy/backup.sh` |
| Сколько сейчас матчей | `curl -s localhost:8080/status` |
